# Chapter 2 — The New Attack Surface Is Inside the Operator

## Chapter job
Map where exposure can enter and spread across a service provider. This chapter is about the *location and shape of exposure*, not incident-response speed (Chapter 3).

## Argument spine
1. OSS/BSS, network and IT environments, cloud, customer data, and suppliers create an interdependent operating ecosystem.
2. Essential legacy, distributed ownership, and constrained maintenance windows make that ecosystem hard to inventory.
3. AI features and agent integrations can introduce new data paths, identities, and tool access that conventional inventories miss.
4. Leaders need an ownership-backed view of consequential AI and agent use before scaling it.

## Evidence and examples to develop
- Ground examples in documented operator architecture or clearly labeled composite scenarios.
- Seek recent primary evidence on AI governance, agent access, or telecom supply-chain exposure.
- Avoid presenting a generic enterprise AI inventory as sufficient for an operator.

## Reader decision
Can leadership identify which AI-enabled actors can access consequential operator systems, data, and suppliers?
